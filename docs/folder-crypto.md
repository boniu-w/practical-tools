# 文件夹加密与恢复

## 操作方式与兼容性

“文件夹加密”选择库中一个公钥、输入目录及新的完整输出文件名（建议 `目录名.zip.gpg`）。程序将目录内容打包为 ZIP，再进行 PGP 加密，保留相对路径、文件字节和空目录，不包含源目录的最外层名称。

“文件夹解密”选择含私钥的库记录、加密归档及新的恢复目录。私钥和解锁口令从密钥库按需读取，不填入界面。选择输出位置时挑选已有父目录，界面建议一个新目录名，也可编辑完整路径。

沿用原 WPF 的“ZIP → GPG”格式，并通过双向互读测试：旧版生成的普通归档可在新版恢复，新版归档可用旧版 GPG + ZipFile 管线解密/解压。它不是对目录中每个文件分别加密，不提供多任务批次或逐文件跳过失败；任一条目失败即终止整次归档。

## 输出与临时内容

- 输出文件或恢复目录必须不存在，不覆盖，也不合并已有目录。父目录需预先存在。
- 加密输出不能位于输入目录内，避免把输出或临时内容带入归档。
- 输入内容只读，原文件不删除；读入的文件元数据及目录修改时间在打包期间重新检查，检测到变动则拒绝发布。它不是原子文件系统快照，请对稳定目录操作。
- 明文 ZIP、解压中的目录均暂存在输出盘的 `.practical-tools-folder-*` 私有目录。Windows 创建时设置当前用户 ACL，Unix 使用 `0700` 目录；恢复文件使用 `0600` 创建，子目录使用 `0700`。Windows 结果目录保留私有根的 ACL。
- ZIP 先完成 PGP 完整性校验，再做目录检查/解压。全部成功后移走完整结果，使用同盘重命名发布；发布前再次拒绝已有输出。不会从归档中的文件名推断最终输出路径。
- 正常取消或异常会清理本次拥有的暂存内容；未完成的目录或密文不发布。临时目录清理若失败会导致任务报错。强制结束进程、断电或卷断开时可能有遗留，需要检查所选输出盘的临时目录；没有安全擦除或启动时自动清理遗留功能。

目标盘须能同时容纳明文 ZIP 和暂存结果。权限隔离效果仍依赖平台和文件系统；当前仅在 Windows 环境验收了私有 ACL，macOS/Linux 模式与外置/共享文件系统需要实测。

## 进度与取消

显示枚举、打包、PGP 加密/解密与完整性校验、ZIP 检查、解压和发布阶段，以及当前条目和阶段字节数。按约 100 ms 节流更新，阶段完成仍会发送最终进度；数字表示当前阶段，不是整次任务的统一百分比。

点击取消或切换离开此页会请求停止。按文件/读取块及发布边界检查取消，密码学库内部工作与系统 I/O 仍可能延迟响应。发布重命名是提交点，已经完成发布的结果不会因随后点击取消而删除。

## 归档检查与限制

默认值：最多 100,000 个归档条目；原始/展开数据总量最多 20 GiB，明文 ZIP 也最多 20 GiB。服务可传入限制配置，当前 UI 使用默认值。PGP 压缩嵌套最多 8 层，文件夹归档必须带有完整性保护；本应用和原 WPF 的生成格式满足该条件。

解压前会预检普通 ZIP/ZIP64 中央目录并核对声明/实际条目数，避免先分配超量条目集合。条目名称按相对路径处理：拒绝绝对路径、反斜杠、`.`/`..`、控制字符、驱动器/ADS 语法、Windows 保留名、结尾点/空格、重复名称、大小写/Unicode 别名及文件/目录冲突。名称最多 1024 个 UTF-16 单元，中央目录名称最多 4096 字节。

源目录中遇到符号链接/重解析点会整次失败，不会悄悄省略；归档中的链接、特殊类型、分卷或额外 ZIP 加密条目拒绝。不可定位的输入流拒绝。ZIP 展开时还核对实际读取长度并限制总量，不信任路径或长度声明。

只承诺文件内容、普通目录结构与空目录，不保存源 ACL、执行位、NTFS ADS、硬链接关系或完整时间/扩展属性。恢复目录采用新的私有权限与创建时间；不是系统备份格式。普通 UTF-8 ZIP/ZIP64 为主要兼容目标，其他 ZIP/PGP 变种可能被拒绝。
