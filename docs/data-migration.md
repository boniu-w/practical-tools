# Windows 旧库与跨机器数据迁移

## 操作流程

1. 完全关闭原 WPF 程序，备份原安装目录中的 `Sqlite/sqlite-PracticalTools.db` 及其辅助文件。
2. 在原 Windows 用户账户下运行新版 Avalonia Windows 版本，完成新版激活，然后打开“数据迁移”。发布版本入口为 `publish-win-x64/PracticalTools.Avalonia.exe`。
3. 输入至少 12 字符的迁移口令并再次确认，选择旧数据库，点击“旧库 → 迁移包”，保存到新的 `.ptmigration` 文件。不要选择覆盖旧库或已有迁移包。
4. 将迁移包带到目标电脑，在新版“数据迁移”中选择包并输入同一迁移口令，点击“验证并预览”。预览显示四类数据数量和密钥指纹（界面最多展示 10 个）。此时没有写入数据库。
5. 核对后点击“确认导入”。成功后显示各类新增数和总跳过数；切换到密钥库或刷新即可选用密钥。

在新版之间迁移时，使用“当前数据 → 迁移包”，无需旧 Windows 或 DPAPI。目标端使用自己的本地保护密钥重新加密口令，不复制源端 `secret-protection.key`。

Windows Avalonia 自包含发布命令：

```powershell
dotnet publish PracticalTools.Avalonia/PracticalTools.Avalonia.csproj -c Release -r win-x64 --self-contained true -o ./publish-win-x64
```

## 数据范围与冲突策略

| 数据 | 迁移范围 | 冲突判定 |
|---|---|---|
| GPG 密钥 | 公私钥、解锁口令、名称、说明及模型中的其他元数据 | 主密钥指纹 |
| 黑名单 | `Blacklist` 映射字段 | 记录 ID |
| 扫描记录 | `DuplicateFiles` 映射字段 | 记录 ID |
| 文件记录 | `MyFile` 映射字段 | 记录 ID |

冲突一律跳过，不覆盖目标数据。批量迁移遇到目标中已有的公钥也会跳过，**不会**自动将其升级为私钥；需要升级时，使用密钥库中的单独私钥文件导入功能。GPG 新记录分配新 ID，其他三类保留原 ID；源包内部重复项同样按上述规则跳过。可重复导入同一包，不重复添加已有记录。

不迁移激活记录、本地保护密钥、日志、未映射的其他表；不会复制被扫描/管理的实际文件，也不会将 Windows 文件路径转换为 Mac/Linux 路径。扫描记录可在“重复扫描”的只读记录区查看，不能直接作为删除依据；文件管理和黑名单页面尚待迁移。

GPG 密钥材料和口令经过验证，公私钥主指纹必须匹配；私钥材料不完整、口令无法解锁或格式异常时，整包失败。公钥证书及子钥保留自源公钥环，有效期与位数按密钥材料重建；这不是信任链或吊销状态验证工具。

## 旧库读取与保护

- 只以 `Mode=ReadOnly`、关闭连接池及读取事务打开旧库，不运行 `EnsureCreated`、格式升级、`rekey` 或替换旧库。
- 通过完整 SQLite 文件头区分明文库与 SQLCipher 库；加密库仅支持原程序使用的数据库密码和当前 SQLCipher 兼容配置。
- 旧版本缺少可选列或上述部分表时使用模型默认值/空列表；至少要存在一个已知数据表，不接受任意 SQLite 数据库。
- DPAPI 由数据提供者头识别，在原 Windows 用户下严格解密；损坏或无法解开的 DPAPI 密文不会退回明文。旧明文口令也必须能实际解锁私钥才能导出。
- 新版 `pt-aesgcm:` 口令格式不走旧库路径，请使用新版“当前数据 → 迁移包”。直接旧库导出只开放于 Windows。

## 包格式与失败规则

版本 1 文件布局为 `PTMIG01\n`（8 字节）+ 随机盐（16）+ 随机 nonce（12）+ 认证标签（16）+ 加密 JSON。JSON 的 `SchemaVersion` 为 1；包含创建时间和上述四类数据，不包含激活。

使用 PBKDF2-HMAC-SHA256、600,000 次迭代派生 32 字节密钥，再以 AES-256-GCM 加密；格式魔数作为关联数据。盐与 nonce 每次随机生成。迁移口令不同于私钥口令、激活码和本地保护密钥。遗失迁移口令无法打开迁移包；请保留原库及其可用账户。

包大小上限为 64 MiB，密钥最多 10,000 条，其他三类合计最多 100,000 条。导出只将密文写入临时文件，刷盘后移动到新文件名；不覆盖已有输出，也不写解密后的 JSON 临时文件。明文 JSON/派生密钥的字节数组用后清零，托管字符串仍不保证可清零。

导入先认证与校验数据，再在一个目标数据库事务内合并。任意校验或写入失败都不留下部分记录，也不改变目标激活记录。预览摘要绑定包内容；口令/文件选择变化会清除预览，预览后外部替换包时要求重新预览。

当前默认策略是保留目标记录，尚无覆盖/合并冲突选择、自动迁移其他表、取消长批次、主密钥轮换或在线复制旧库功能。应在关闭旧程序后操作；Windows 同账户夹具与窗口测试已通过，其他账户和 macOS/Linux 实机流程仍待平台验收。

技术参考：[SQLite 只读连接](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/connection-strings)、[.NET PBKDF2](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.rfc2898derivebytes.pbkdf2?view=net-8.0)。
