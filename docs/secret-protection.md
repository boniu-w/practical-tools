# 本地口令保护与恢复

## 使用范围

Avalonia 的 `GpgFile.Passphrase` 通过注入的 `ISecretProtector` 写入版本化 AES-256-GCM 密文。原 WPF 上下文未注入保护器时，继续使用原 DPAPI 格式和旧明文兼容逻辑。Avalonia 不接受旧明文或 DPAPI 密文作为新格式口令，旧库导入仍待后续阶段实现。

密钥库页面现已接入此存储路径：生成的密钥自动入库，导入私钥会验证口令。列表与详情只读取元数据，不读取口令与私钥；加解密及导出时按需读取。手工导出公私钥仍可作为额外备份。

## 格式和密钥

- 保护格式：`pt-aesgcm:v1:` 加 Base64 编码的 `nonce(12 字节) | tag(16 字节) | ciphertext`。
- 每次写入使用密码学随机源生成新的 96 位 nonce，不以时间或普通随机数生成。nonce 唯一性采用随机方案，碰撞概率随写入量增长，并非持久化计数器方案。
- 关联数据固定为 `PracticalTools/GpgFile.Passphrase/v1`，绑定字段用途和格式版本。
- 本地密钥为密码学随机生成的 32 字节，位于 `AppDataPaths.SecretKeyPath`：用户数据目录中的 `secret-protection.key`。
- Windows 在创建临时密钥文件时即设置仅当前用户允许访问的独立 ACL；Unix 创建权限为 `0600`。写入刷盘后通过不覆盖的文件移动发布，避免读取半成品或替换已有密钥。
- 密钥不长期缓存在保护器中；每次操作读取文件，使用后的密钥字节和临时明文字节清零。调用方的 .NET 字符串不保证可清零。
- 空字符串保持为空，纯空白等非空口令仍按原值加密保存。

使用的是本地原始密钥文件，不依赖系统钥匙串或主密码。它可随匹配数据库恢复到另一个用户数据目录；获得数据库和密钥文件的主体也能解密口令，因此备份应加密并限制访问。本机制不防御已控制当前用户账户的程序。

实现参考 [.NET AesGcm](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.aesgcm?view=net-8.0) 和[创建带权限的文件](https://learn.microsoft.com/en-us/dotnet/api/system.io.filesystemaclextensions.create?view=net-8.0)。

## 初始化与失败行为

启动在初始化数据库后检查是否有 `GpgFile` 记录。不存在本地保护密钥时，仅空密钥库允许首次创建；已有任何密钥记录则拒绝生成替代密钥，并提示恢复备份。该检查采用保守策略，空口令记录也计入已有记录。

已存在但长度不正确的密钥文件不会被覆盖。加解密操作本身永远不会创建密钥。缺少密钥、密文篡改、错误密钥、未知版本或无效格式都会抛出异常；不会退回明文或原密文。启动只检查文件存在性和长度，32 字节错误密钥在读取受保护口令时由认证校验拒绝。

EF Core 模型缓存键包含保护器实例，转换器仅捕获该实例，避免复用其他服务容器或数据目录的保护策略。每个 Avalonia 服务容器共用单例保护器，数据库上下文仍使用独立作用域。

## 备份与恢复规则

1. 完全退出应用，再备份整个用户数据目录，至少同时保存 `sqlite-PracticalTools.db` 和 `secret-protection.key`。若存在数据库 WAL/SHM 等辅助文件，一并保存；不要在线只复制主数据库文件。
2. 将备份作为敏感数据加密保存。不要只备份数据库，也不要把密钥文件上传到代码仓库。
3. 恢复时退出应用，将匹配的数据库和密钥放回目标用户数据目录。保留恢复前原目录，避免覆盖唯一可用副本。
4. 确认目标目录与密钥仅供目标用户访问：Unix 密钥 `0600`、数据目录 `0700`；Windows 将文件访问权限限制为目标用户。备份工具可能不保留权限，应用目前不自动修复恢复文件的 ACL/权限。
5. 启动并核验口令读取。密钥丢失或错配时应从匹配备份恢复，不能通过删除密钥、重建密钥或重新激活来恢复原口令。

跨机器完整数据导入、迁移包、密钥轮换及系统钥匙串集成不在本阶段交付范围内。
